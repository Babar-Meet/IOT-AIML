# IOT-AIML

Real-time hand gesture recognition and finger counting system that maps detected finger counts (0–5) to configurable IoT API endpoints. Built with MediaPipe Hand Landmarker and OpenCV.

---

## Purpose

IOT-AIML bridges computer vision and Internet of Things (IoT) control by turning hand gestures into actionable triggers. The application solves the problem of contactless device control: a user shows a number of fingers to a webcam, holds the gesture for one second, and the system fires an HTTP request to a mapped smart device (light, fan, AC, etc.). It also serves as a standalone finger-counting demonstration tool when operating in Counting mode.

The intended audience includes developers and hobbyists working on vision-based human-computer interaction, smart home automation, and real-time computer vision systems.

---

## Features

- **Real-time hand landmark detection** using MediaPipe Tasks API (Hand Landmarker model)
- **Orientation-independent finger counting** — detects 0–5 extended fingers using geometric straightness ratios, robust to hand rotation and mirroring
- **Dual operating modes** — _Counting_ (visual feedback only) and _IOT_ (fires HTTP GET requests)
- **1-second debounce mechanism** — gesture must be held for one full second before triggering, preventing accidental activation
- **On-screen HUD** — displays mode, current finger count, per-hand breakdown, FPS, and trigger confirmation messages
- **Pulsating trigger flash animation** — visual confirmation when a gesture is locked in or an API call is made
- **Runtime config hot-reloading** — click the CONFIG button in the top-right corner to load a new JSON configuration without restarting
- **Dual-hand support** — detects up to two hands simultaneously and sums their finger counts
- **Skeleton overlay** — draws hand landmarks and connections on the video feed
- **Video file playback** — supports processing pre-recorded video files via `--video` argument
- **Standalone executable build** — PyInstaller specs and build script for Windows distribution

### Directory and File Descriptions

#### `core/config_manager.py`
Loads JSON configuration files containing the operating mode (`"Counting"` or `"IOT"`) and a dictionary of finger-count-to-endpoint mappings. If no config file exists at the configured path, a default config is created automatically. The `reload()` method allows swapping configurations at runtime.

#### `core/iot_manager.py`
Implements the gesture debounce logic and HTTP trigger dispatch. On each frame it receives the current finger count; when the same count is held for `debounce_duration` (default 1.0 s), the gesture is considered intentional. In Counting mode, this is logged to console. In IOT mode, an asynchronous HTTP GET request is fired via a daemon thread to the mapped endpoint URL.

#### `detector/hand_detector.py`
Wraps MediaPipe's `HandLandmarker` (RunningMode.IMAGE) to detect up to two hands per frame. Finger extension is determined using orientation-independent geometric straightness ratios: for the thumb, the ratio of tip-to-MCP distance over the path through the IP joint is combined with a check that the thumb tip is farther from the pinky base than the IP joint. For the other four fingers, tip-to-MCP straightness is combined with a wrist-distance sanity check. The method works regardless of hand rotation or mirroring.

#### `ui/renderer.py`
Renders the video overlay using OpenCV primitives. Draws a semi-transparent top bar showing the operating mode, an interactive CONFIG button area, the current finger count (with per-hand breakdown when two hands are detected), a large semi-transparent digit in the center of the frame, and a pulsating trigger flash message when a gesture is locked in or an API call is made.

#### `utils/helpers.py`
Provides geometry utility functions: `calculate_angle` (angle at a point formed by three points), `distance` (Euclidean), `midpoint`, `clamp`, `bbox_center`, `bbox_area`, and `smooth_value` (mode-based temporal smoothing over a sliding window). These are available for use but not directly imported by the current runtime modules.

#### `main.py`
Application entry point. Parses CLI arguments (`--video` for video file path, `--camera` for camera index), initializes `ConfigManager`, `IOTManager`, `HandDetector`, and `Renderer`, opens the video capture source, and runs the main loop. Each iteration:
1. Checks for runtime config reload (triggered by mouse click on CONFIG button)
2. Reads a frame, optionally mirrors it (camera only)
3. Runs hand detection
4. Updates IOT debounce and trigger logic
5. Renders the HUD overlay
6. Calculates and displays FPS
7. Handles keyboard quit (`Q`, `ESC`) and window close events

#### `config.py`
Constants for camera index (`0`), capture resolution (`1280×720`), and window title (`"IOT-AIML"`).

## Architecture

### High-Level Design

The application follows a pipeline architecture with four distinct stages executed sequentially per frame:

```
Video Source (Camera / File)
        |
        v
  HandDetector   ────> finger count, landmarks
        |
        v
  IOTManager     ────> trigger decision (debounced)
        |
        v
  Renderer       ────> HUD overlay on frame
        |
        v
  OpenCV Window  ────> display
```

### Request / Response Flow

The application does not expose a network server. All I/O is outbound:

1. **User shows gesture** → Camera captures frame
2. **HandDetector** processes frame → finger count extracted
3. **IOTManager** debounces the count → if confirmed, fires HTTP GET to mapped endpoint
4. **HTTP response** status and body (first 50 chars) logged to console
5. **Renderer** displays "TRIGGERED" flash on frame

### Data Flow

- **Frame**: BGR image → mirrored (camera only) → converted to RGB → MediaPipe `mp.Image` → landmark detection → BGR (for overlay drawing)
- **Count**: raw count from `HandDetector.detect()` → `IOTManager.update_count()` → debounce state machine → trigger output or `None`
- **Config**: JSON file on disk → `ConfigManager.load_config()` → `mode` (string) + `iot_endpoints` (dict) → consumed by IOTManager and Renderer
- **FPS**: rolling average of per-frame timing, recalculated every 0.5 s

### State Management

State is held in-memory within class instances (no persistence layer):
- `IOTManager`: tracks `current_count`, `count_start_time`, `last_triggered_count` — the debounce state machine
- `Renderer`: tracks `trigger_flash_count` and `trigger_value` — the flash animation counter
- `ConfigManager`: tracks `config_path`, `mode`, `iot_endpoints` — the active configuration

### Error Handling Strategy

- **Camera/source open failure**: prints error and exits with code 1
- **Frame read failure (camera)**: sleeps 10 ms and retries
- **Frame read failure (video)**: prints "Video finished" and exits loop cleanly
- **Config load failure**: prints error and continues with current values
- **Config file not found**: creates a default config file automatically
- **API call failure**: caught in the worker thread, logs error message; does not crash the application
- **KeyboardInterrupt**: caught in `try/finally` to release camera and destroy windows

## How It Works

1. **Startup**: The application opens a webcam (or video file), initializes the MediaPipe hand landmarker, loads the JSON configuration, and opens a resizable OpenCV window.

2. **Frame capture**: Each iteration reads one frame from the source. If the source is a camera, the frame is mirrored horizontally so the user sees a natural mirror image.

3. **Hand detection**: The frame is converted from BGR to RGB and passed to MediaPipe's `HandLandmarker`, which returns up to two sets of 21 landmarks each (one per detected hand). The landmarker is used in `IMAGE` mode (single-shot per frame). Landmark coordinates are normalized to [0, 1] relative to image dimensions.

4. **Finger counting**: For each hand, five finger states (0 = curled, 1 = extended) are computed using geometric ratios:
   - **Thumb**: straightness ratio of tip-to-MCP path vs. the path through the IP joint (> 0.85 threshold) plus a check that the thumb tip is farther from the pinky base than the IP joint (ensures abduction away from palm).
   - **Index, middle, ring, pinky**: straightness ratio of tip-to-MCP direct distance vs. the path through the PIP joint (> 0.85 threshold) plus a check that the fingertip is farther from the wrist (landmark 0) than the PIP joint (eliminates curled fingers viewed from a perspective that falsely appears straight).
   - Counts from both hands are summed.

5. **Debounce and trigger**: The total finger count is passed to the IOTManager. If the count matches the previous frame's count, a timer advances. When the timer reaches 1 second of continuous hold, the gesture is locked:
   - **Counting mode**: "LOCKED: N" is logged and flashed on screen.
   - **IOT mode**: A daemon thread fires an HTTP GET to the endpoint mapped to that finger count. The response code and first 50 characters of the body are logged.

6. **Rendering**: The Renderer draws a semi-transparent top bar (mode, CONFIG button, count, FPS), a large translucent digit in the center of the frame, and a colored flash message for triggered gestures.

7. **Display**: The composited frame is shown in the OpenCV window. The loop repeats until the user presses Q/ESC or closes the window.

8. **Shutdown**: The camera is released, OpenCV windows are destroyed, and the Tkinter root is cleaned up.
